CareLink Build Roadmap
======================

Project Summary
---------------
CareLink is a web-based smart health referral system for Barangay Health Centers and the Koronadal City Health Center. Its purpose is to replace manual paper-based referrals with a digital workflow that supports patient registration, referral submission, city health center review, automated queue prioritization, SMS notifications, referral tracking, reporting, and administrative control.

Primary goals:
1. Streamline referral processing between barangay health centers and the city health center.
2. Automatically classify approved referrals using a rules-based priority algorithm.
3. Send SMS updates for approval, appointment reminders, and missed referrals.
4. Track referral status from submission to completion.
5. Provide analytics for referral volume, queue trends, completion rates, and SMS activity.
6. Enforce role-based access for Super Admin, Barangay Health Center Staff, City Health Center Staff, and Patients.

Recommended Technology Stack
----------------------------
Backend:
- Node.js
- Express.js or Fastify for the API backend
- JWT or secure cookie-based authentication
- node-cron for scheduled reminders
- BullMQ, Bee-Queue, or a simple database-backed job table for SMS jobs

Database:
- MySQL as the main relational database
- phpMyAdmin/phpMySQL-style database management for creating, inspecting, importing, and backing up tables

Frontend:
- Vite.js for the web frontend
- React, Vue, or vanilla JavaScript depending on team preference
- Tailwind CSS
- Responsive layouts for desktop and mobile patient views

External Services:
- Semaphore SMS Gateway for patient notifications

Development Tools:
- Visual Studio Code
- Node.js and npm
- phpMyAdmin or an equivalent MySQL administration tool
- Git
- Figma for UI wireframes
- Google Chrome or another modern browser for testing

Deployment:
- Deploy the Vite frontend to Vercel, Netlify, or another static hosting provider.
- Deploy the Node.js API to a Node-compatible host such as Render, Railway, VPS hosting, or a similar service.
- Use a production MySQL database.
- Configure HTTPS, environment variables, API process management, queue workers, and scheduler jobs.

1. Super Admin
   - Log in and access admin dashboard.
   - Manage user accounts.
   - Manage health center profiles.
   - Configure priority scoring weights and thresholds.
   - Configure SMS notification triggers.
   - View audit logs and system activity.
   - View high-level system metrics.

2. Barangay Health Center Staff
   - Log in and access barangay dashboard.
   - Register patients.
   - Create and update patient records.
   - Submit digital referral forms.
   - Track submitted referral statuses.
   - View referral history for their assigned health center.

3. City Health Center Staff
   - Log in and access city dashboard.
   - View incoming referrals.
   - Review referral details and patient records.
   - Approve or reject referrals.
   - Trigger automatic priority scoring and queue assignment on approval.
   - Manage the prioritized queue.

4. Patient

Core Referral Workflow
----------------------
1. Barangay staff logs in.
2. Barangay staff registers or selects a patient.
3. Barangay staff submits a digital referral form with:
   - patient details
   - referral reason
   - clinical urgency
   - referral type
   - demographic flags such as senior citizen, pregnant, or PWD
4. System stores the referral with status submitted.
5. City staff receives the referral in the incoming referral queue.
6. City staff reviews the referral.
7. If rejected:
   - status becomes rejected
   - rejection reason is saved
   - audit log is recorded
8. If approved:
   - status becomes approved
   - rules-based priority score is computed
   - queue entry is created
   - queue number is assigned
   - status becomes queued
   - SMS approval alert is sent to the patient
9. Patient can view referral and queue status using the SMS details.
10. City staff marks the patient as served/completed, missed, or archived.
11. Analytics dashboards update based on referral and queue records.

Referral Status Lifecycle
-------------------------
submitted -> under_review -> approved -> queued -> completed
submitted -> under_review -> rejected
queued -> missed
missed -> archived

Keep status transitions strict. Do not allow completed referrals to return to active queue states unless an administrator explicitly reopens them with an audit log entry.

Rules-Based Queue Priority Algorithm
------------------------------------
CareLink must not use machine learning or AI for priority assignment. Use deterministic rules and configurable weights.

Suggested scoring categories:
1. Clinical urgency
   - emergency: 100 points
   - urgent: 60 points
   - routine: 20 points

2. Demographic classification
   - senior citizen: 25 points
   - pregnant: 25 points
   - PWD: 25 points
   - no vulnerable classification: 0 points

3. Referral type
   - emergency: 50 points
   - specialist consultation: 30 points
   - follow-up: 15 points
   - routine: 5 points

Suggested priority tiers:
- Priority 1 Emergency: score >= 100 or clinical_urgency = emergency
- Priority 2 Vulnerable Group: score >= 50 or patient is senior, pregnant, or PWD
- Priority 3 Standard Referral: all other approved referrals

Queue ordering:
1. Priority level ascending, with Priority 1 first.
2. Higher priority score first.
3. Earlier approval time first.

Example pseudocode:

score = clinical_urgency_points + demographic_points + referral_type_points

if clinical_urgency == "emergency" or score >= 100:
    priority_level = "priority_1_emergency"
elif patient_is_senior or patient_is_pregnant or patient_is_pwd or score >= 50:
    priority_level = "priority_2_vulnerable"
else:
    priority_level = "priority_3_standard"

Security and Privacy Requirements
---------------------------------
1. Enforce authentication for all staff modules.
2. Enforce role-based authorization through middleware and policies.
3. Limit barangay staff access to patients and referrals from their assigned health center.
4. Limit patient public pages to only the minimum required status data.
5. Use signed URLs or secure lookup tokens for patient tracking links.
6. Hash passwords using bcrypt or argon2.
7. Validate all form inputs.
8. Sanitize free-text display.
9. Protect the API with appropriate CSRF protection for cookie sessions, strict CORS rules, rate limiting, and secure HTTP headers.
10. Record important actions in audit_logs:
    - login
    - user creation/update/disable
    - health center changes
    - priority rule changes
    - referral submission
    - referral approval/rejection
    - queue status changes
    - SMS trigger configuration changes
11. Keep API credentials in .env only.
12. Never commit .env or production credentials.

Validation Rules
----------------
Patient:
- name fields required
- birth date required and not in future
- sex required
- contact number required and must match Philippine mobile format where possible
- address required

Referral:
- patient required
- referral reason required
- clinical urgency required
- referral type required
- receiving health center required

Review:
- approval requires appointment date/time if the workflow uses scheduled referrals
- rejection requires rejection reason

Priority rules:
- score value must be numeric and non-negative
- thresholds must be numeric and ordered logically

Known Scope Limits
------------------
1. CareLink only covers referrals from barangay health centers to the Koronadal City Health Center.
2. It does not cover referrals to tertiary hospitals, private facilities, or other government institutions.
3. It is not a full EMR system.
4. It does not include diagnosis, prescription management, or clinical decision support.
5. It does not use AI or machine learning for prioritization.
6. SMS reliability depends on mobile network availability and the SMS provider.

Minimum Viable Product Definition
---------------------------------
The MVP is complete when:
1. Staff can log in by role.
2. Super Admin can manage users and health centers.
3. Barangay staff can register patients and submit referrals.
4. City staff can approve or reject referrals.
5. Approved referrals automatically receive priority scores and queue numbers.
6. Patients receive approval SMS messages.
7. Patients can view referral and queue status.
8. City staff can mark referrals completed or missed.
9. Basic analytics show referral counts, queue counts, priority distribution, completion rate, and SMS results.
10. Audit logs capture major system actions.

Recommended Build Principle
---------------------------
Build the system around the referral lifecycle first. Authentication, patient records, referral submission, review, priority scoring, queue assignment, and status tracking are the core. SMS automation, analytics, surveys, and advanced reports should build on top of that stable workflow.
